## 1. Идея

Бинарный поиск ищет **границу** там, где ответ на вопрос «подходит ли `i`?» меняется один раз:

```
i:      0  1  2  3  4  5  6  7
check:  F  F  F  F  T  T  T  T
                   ^ граница
```

Нужно два условия:

- **монотонность**: если `check(x)` верно, то верно и `check(x+1)` (или наоборот на всей области);
- **быстрая проверка** `check(x)`.

Тогда граница находится за `O(log N)` вызовов `check`. Отсортированный массив здесь лишь частный случай, где `check(i)` это `array[i] >= x`.

## 2. Поиск элемента в массиве

Пусть дан отсортированный массив из `n` элементов, нужно ответить, встречается ли в нём `x`.

### Метод 1: постоянная проверка середины

```cpp
int a = 0, b = n-1;

while (a <= b){
    int k = (a+b)/2;
    if (array[k] == x){
        // найден x
    }
    // сдвигаем границы
    if (array[k] < x) a = k+1;
    else b = k-1;
}
```

Сложность `O(log n)`: размер отрезка каждый раз уменьшается вдвое.

### Метод 2: прыжками

```cpp
int k = 0;
for (int b = n/2; b >= 1; b /= 2){
    while (k + b < n && array[k+b] <= x) k += b;
}
if (array[k] == x){
    // нашли элемент
}
```

Прыжки идут длиной `n/2, n/4, ..., 1`. После цикла `k` — **последний** индекс, для которого `array[k] <= x`. Каждая длина используется не более двух раз, поэтому всё тоже `O(log n)`.

### Границы: lower_bound и upper_bound

Чтобы посчитать, сколько элементов лежит в `[l, r]` (`E.cpp`), ищут две границы:

```cpp
// lower_bound: первый индекс, где v[mid] >= l
int lo = 0, hi = n;
while (lo < hi){
    int mid = (lo + hi) / 2;
    if (v[mid] >= l) hi = mid;
    else lo = mid + 1;
}
int left = lo;

// upper_bound: первый индекс, где v[mid] > r
lo = 0; hi = n;
while (lo < hi){
    int mid = (lo + hi) / 2;
    if (v[mid] > r) hi = mid;
    else lo = mid + 1;            // именно mid + 1, иначе цикл зависнет
}
int right = lo;

cout << right - left;             // сколько элементов в [l, r]
```

Ближайший к `x` элемент (`F.cpp`): находим `lower_bound`, затем сравниваем `a[l-1]` и `a[l]`, не забыв про случаи `l == 0` и `l == n`.

### То же самое в STL

| Что нужно                         | STL                                    |
|-----------------------------------|----------------------------------------|
| Первый элемент `>= x`             | `lower_bound(a.begin(), a.end(), x)`   |
| Первый элемент `> x`              | `upper_bound(a.begin(), a.end(), x)`   |
| Есть ли `x`                       | `binary_search(a.begin(), a.end(), x)` |
| Сколько элементов равно `x`       | `upper_bound - lower_bound`            |

Индекс получается вычитанием: `lower_bound(a.begin(), a.end(), x) - a.begin()`.

## 3. Бинпоиск по ответу

Бинпоиск по ответу ищет **границу**, а не проверяет существование конкретного значения. Применяется, когда нужно найти **минимальное** или **максимальное** `x` с некоторым свойством, а проверить «годится ли конкретное `x`» проще, чем найти его напрямую.

План:

1. Понять, что является ответом `x` (время, длина, скорость, расстояние, номер).
2. Написать `check(x)` / `valid(x)`, которая **монотонна** по `x`.
3. Выбрать границы `l` и `r` с запасом.
4. Запустить один из циклов ниже.

### Минимальное `x`, для которого `check(x)` истинно

```cpp
long long l = 0, r = /* заведомо хорошее */;   // ответ лежит в [l, r]

while (l < r){
    long long mid = (l+r)/2;
    if (check(mid)) r = mid;
    else l = mid+1;
}
// l == r, это и есть ответ
```

Пример (`2020B.cpp`): минимальное `n`, для которого `n - floor(sqrt(n)) >= k`:

```cpp
bool valid(long long mid, long long k){
    return mid - (long long)sqrtl(mid) >= k;
}
// l = 1, r = 2e18, дальше цикл выше
```

### Максимальное `x`, для которого `check(x)` истинно

```cpp
while (l < r){
    long long mid = (l+r+1)/2;      // +1 обязателен
    if (check(mid)) l = mid;
    else r = mid-1;
}
// l == r, это ответ
```

`+1` нужен, потому что при `l = mid` и обычном `mid = (l+r)/2` на отрезке из двух элементов `mid == l`, и цикл никогда не закончится.

### Форма `r - l > 1` (`1612C.cpp`, `1907D.cpp`)

`l` — заведомо плохое значение (можно выйти за диапазон ответов, например `-1`), `r` — заведомо хорошее. `check` на границах не вызывается:

```cpp
long long l = -1, r = 1e9 + 1;

while (r - l > 1){
    long long mid = l + (r - l) / 2;
    if (check(mid)) r = mid;
    else l = mid;
}
// ответ r
```

### Метод прыжков для ответа

```cpp
int x = -1;
for (int b = z; b >= 1; b /= 2){
    while (!valid(x+b)) x += b;
}
int k = x+1;       // первое хорошее значение
```

`z` — степень двойки, не меньше размера диапазона ответов. `x` в конце — **последнее плохое** значение, поэтому ответ `x+1`. Важно, чтобы `valid` была определена и для `x+b`, которые могут слегка выйти за диапазон.

### Если правая граница неизвестна: удвоение

Можно предположить, что ответ находится недалеко от правой границы, поэтому растим её, пока она не станет хорошей:

```cpp
long long r = 1;
while (!good(r)) r *= 2;
long long l = r/2;
// дальше обычный цикл while (l < r) на отрезке [l, r]
```

### Задачи «найти k-й элемент»

Нужно найти k-й по величине элемент, не строя сам массив. Достаточно уметь считать `count(x)` — сколько элементов `<= x`.

**Идея.** Ответ — это минимальное `x`, для которого `count(x) >= k`. Например, для значений `1 2 2 5 7` и `k = 3`: `count(1) = 1`, `count(2) = 3`, поэтому ответ `2`.

Значит, это обычный бинпоиск на минимум, где `x` подходит, если `count(x) >= k`:

```cpp
if (count(mid) >= k) r = mid;     // элементов хватает, mid подходит, ищем меньше
else l = mid+1;                   // элементов мало, нужно x побольше
```

**Как это записано в `L.cpp` и `M.cpp`.** Функция там написана наоборот и возвращает `count < k`, то есть `true` значит «`x` слишком мал». Поэтому ветки меняются местами, а смысл остаётся тем же:

```cpp
if (check(mid)) l = mid+1;        // check == true: x слишком мал, ответ правее
else r = mid;
```

В `ItmoAcademy/1.cpp` условие `count <= k`, то есть ищется первое `x`, при котором элементов `<= x` **больше** `k`. Это номер `k` при нумерации с нуля.

Перед циклом всегда полезно проговорить, что значит `true` в вашей функции: «подходит» или «слишком мало».

## 4. Вещественные числа: шаг итераций и eps

Если ответ вещественный, «следующего значения» не существует, поэтому:

- границы двигаются как `l = mid` / `r = mid`, **без** `+1` / `-1`;
- цикл останавливается либо после **фиксированного числа итераций**, либо по условию `r - l > eps`.

### Фиксированное число итераций (надёжнее)

```cpp
double l = 0, r = 10e10;

for (int it = 0; it < 100; it++){
    double mid = (l+r)/2;
    if (check(mid)) r = mid;      // ищем минимум; для максимума поменять ветки
    else l = mid;
}
cout << fixed << setprecision(10) << l;
```

За 100 итераций отрезок уменьшается в `2^100` раз, с огромным запасом.

### Через eps (`H.cpp`)

```cpp
while (r - l > 0.00000000001){
    double mid = (l+r) / 2.0;
    if (mid*mid + sqrtl(mid) >= c) r = mid;
    else l = mid;
}
```

Осторожно: у `double` около 15–16 значащих цифр. Если значения порядка `1e9` и больше, то `r - l` может никогда не стать меньше маленького `eps`, и цикл бесконечный. В таких случаях берите фиксированное число итераций.

## 5. Задачи на минимакс

Формулировки «**минимизировать максимум**» и «**максимизировать минимум**» почти всегда решаются бинпоиском по ответу: вместо поиска оптимального разбиения мы спрашиваем «можно ли добиться значения `x`?» и отвечаем жадностью за `O(n)`.

| Формулировка              | Что ищем          | Цикл                          | Что проверяет `check(x)`                  |
|---------------------------|-------------------|-------------------------------|-------------------------------------------|
| минимизировать максимум   | минимальное `x`   | `mid = (l+r)/2`, `r = mid`    | можно ли, чтобы все значения были `<= x`  |
| максимизировать минимум   | максимальное `x`  | `mid = (l+r+1)/2`, `l = mid`  | можно ли, чтобы все значения были `>= x`  |

Работает потому, что если можно уложиться в `x`, то можно и в `x+1`, то есть `check` монотонна.

### Минимизировать максимум (`ItmoAcademy/B.cpp`)

Разбить массив на не более чем `k` подряд идущих отрезков, чтобы максимальная сумма отрезка была как можно меньше:

```cpp
bool check(vector<int>& a, long long mid, int k){
    int parts = 1;
    long long s = 0;

    for (auto el : a){
        if (el > mid) return false;    // элемент не помещается в отрезок

        s += el;
        if (s > mid){                  // жадно начинаем новый отрезок
            parts += 1;
            s = el;
        }
    }
    return parts <= k;
}
// l = 0, r = 1e15, цикл «минимум»
```

### Максимизировать минимум (`ItmoAcademy/C.cpp`)

Расставить `k` коров по стойлам так, чтобы минимальное расстояние между соседними было максимальным:

```cpp
bool check(long long mid, vector<long long>& st, int n, int k){
    int cows = 1;
    long long last_pos = st[0];

    for (int i = 0; i < n; i++){
        if (st[i] - last_pos >= mid){
            cows += 1;
            last_pos = st[i];
        }
    }
    return cows >= k;
}
// l = 0, r = 1e11, цикл «максимум» с (l+r+1)/2
```

### Ещё пример (`1907D.cpp`)

Минимальное `k` (максимальный прыжок), чтобы пройти через все отрезки. Проверка хранит достижимый отрезок `[L, R]`:

```cpp
L = max(l, L - k);
R = min(r, R + k);
if (L > R) return false;
```

## 6. Тернарный поиск

Бинпоиск ищет границу в **монотонной** последовательности. Если функция **унимодальна** (сначала строго убывает, потом строго возрастает, или наоборот), то нужен экстремум, и для этого служит тернарный поиск (`I.cpp`).

```cpp
double l = 0, r = 1;

for (int i = 0; i < 100; i++){
    double m1 = (2*l + r)/3;
    double m2 = (2*r + l)/3;

    if (f(m1) < f(m2)) r = m2;     // ищем минимум
    else l = m1;
}
cout << fixed << setprecision(10) << (l+r)/2 << '\n';
```

Логика для минимума: если `f(m1) < f(m2)`, то минимум левее `m2`, поэтому `r = m2`; иначе он правее `m1`, поэтому `l = m1`. Для максимума знак сравнения меняется.

Каждая итерация оставляет `2/3` отрезка, 100 итераций с огромным запасом.

### Целочисленный вариант: бинпоиск по наклону

Для целых аргументов удобнее не делить на трети, а сравнивать соседние значения:

```cpp
long long l = L, r = R;            // f строго убывает, затем строго возрастает
while (l < r){
    long long mid = (l+r)/2;
    if (f(mid) > f(mid+1)) l = mid+1;   // ещё убываем, минимум правее
    else r = mid;
}
// l — точка минимума
```

### Когда тернарный поиск ломается

- **Плато.** Если у функции есть участки с одинаковыми значениями не на вершине, сравнение `f(m1)` и `f(m2)` не говорит, куда идти. Нужна **строгая** унимодальность.
- **Несколько экстремумов.** Найдётся какой-то локальный экстремум, не обязательно глобальный.
- **Мелкий отрезок.** Когда `r - l` приближается к машинной точности, сравнение значений бессмысленно, поэтому берут фиксированное число итераций, а не `eps`.

## 7. Шпаргалка

| Задача                                              | Что использовать                         | Остановка                        |
|-----------------------------------------------------|------------------------------------------|----------------------------------|
| Есть ли элемент в отсортированном массиве           | метод 1, метод 2, `binary_search`        | `a <= b` / прыжки до `b = 1`     |
| Сколько элементов в `[l, r]`, ближайший к `x`       | `lower_bound`, `upper_bound`             | `lo < hi`                        |
| Минимальное `x`, для которого `check(x)`            | `(l+r)/2`, `r = mid`, `l = mid+1`        | `l < r`                          |
| Максимальное `x`, для которого `check(x)`           | `(l+r+1)/2`, `l = mid`, `r = mid-1`      | `l < r`                          |
| Правая граница неизвестна                           | удвоение `r *= 2`                        | пока `!good(r)`                  |
| Минимизировать максимум / максимизировать минимум  | бинпоиск по ответу + жадная проверка     | `l < r`                          |
| Ответ вещественный                                  | `l = mid`, `r = mid`                     | 100 итераций или `r - l > eps`   |
| Экстремум унимодальной функции                      | тернарный поиск                          | 100 итераций                     |

Порядок мыслей при решении:

1. Ищу позицию элемента, границу по условию или экстремум функции?
2. Есть ли монотонная проверка по ответу? Если да, то бинпоиск по ответу.
3. Ответ целый или вещественный? Это определяет шаг (`+1` или `= mid`) и условие остановки.
4. Минимум или максимум? От этого зависит `(l+r)/2` или `(l+r+1)/2`.
5. Функция с одним «горбом», а не монотонная? Тернарный поиск.

Сложность: `O(log(диапазон) * T(check))`.

## 8. Типичные ошибки

- **Бесконечный цикл.** `l = mid` вместе с `mid = (l+r)/2` на отрезке из двух элементов не сдвигается. Либо `l = mid+1`, либо `(l+r+1)/2` для варианта «максимум». Ровно эта ошибка стоит во втором цикле `Itmo A&D 2021/E.cpp` (там `else lo = mid;` вместо `lo = mid + 1`): на входе `n=1, a=[1], l=r=1` программа зависает.
- **Неверные границы.** Ответ лежит вне `[l, r]`. Проверяйте крайние случаи: ответ минимальный, максимальный, `n = 1`.
- **`check` не монотонна.** Бинпоиск «сработает», но даст неверный ответ.
- **Инвертированный `check`.** В задачах на k-й элемент у вас `check(x)` истинна при слишком малом `x`, а в задачах на минимум наоборот. Перед написанием цикла проговорите, что значит `true`.
- **Переполнение.** `l + r` для больших границ лучше писать как `l + (r - l) / 2`, а для значений до `1e18` использовать `long long`.
- **`10e10` это `1e11`**, а не `1e10`: мантисса `10e10 = 10 * 10^10`. Аналогично `5*10e8 = 5e9`.
- **eps против больших `double`.** Когда значения порядка `1e9` и выше, берите фиксированное число итераций.
- **Копирование вектора в `check`.** Если параметр объявлен как `vector<...> v` без `&`, вектор копируется на каждый вызов, и решение замедляется в `n` раз. Передавайте по ссылке: `const vector<...>& v`.
- **Путаница `lower_bound` и `upper_bound`.** Первый ищет `>= x`, второй `> x`.
